# Security and publication policy

This software is in development; no production security certification or support SLA is claimed.

Report vulnerabilities privately to **augusto@zilviko.lat**. Do not put credentials, personal records or exploitable details in public issues.

Keep environment files, keys, credentials, uploads, databases, dependencies/builds and agent records outside Git. If sensitive material exists in an earlier commit, deleting it from the current tree is insufficient.

Use disposable local data. Do not run provider, billing, deployment or database-reset commands against real customer environments.

See PUBLICATION_CHECKS.md for recorded checks and limits. A scanner result is supporting evidence, not proof that no sensitive content exists.
